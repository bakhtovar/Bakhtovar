# SmartPay в Blast: как это ложится на проект

Не документация SmartPay, а решение о том, куда её встраивать. Обновляй по мере
того, как интеграция обретает форму.

## Где в продукте появляется оплата

Один якорь в коде уже есть — `lib/features/activation/presentation/activation_screen.dart:139`,
комментарий `TODO(оплата)`. По задуманному флоу официант гасит код, дальше гость
платит из приложения. Сейчас модель другая: скидка включается в заведении, Blast
денег не касается.

Второй кандидат — подписка «Плюс» на экране подписки. **Но она SmartPay не
достанется** (см. ниже).

## Ограничение Apple, которое определяет архитектуру

Из `docs/TODO.md`:

- Подписка «Плюс» — **только In-App Purchase** (правило 3.1.1). Строку
  «Карта / Корти Милли» на экране подписки убрать при подключении оплаты.
  SmartPay здесь запрещён.
- Оплата счёта в заведении — **не IAP** (правило 3.1.3(e), физические товары и
  услуги). Здесь SmartPay уместен, как и Apple Pay или карта.

Вывод: SmartPay берёт только оплату счёта в заведении. Подписку — StoreKit.
Смешивать в одном экране нельзя, Apple снимает такие сборки.

## Что уже построено (8 сентября 2026)

Ветка `feature/smartpay-payments`, проект Supabase «Blast App Dev»
(`lfudcjwkyctodeqaommv`).

| Что | Где |
|---|---|
| Таблица платежей | `smartpay_payments`, деньги в целых дирамах, RLS на чтение своих |
| Расчёт суммы | `smartpay_prepare_payment(user, venue, bill, activation, bank, env)` |
| Запись ответа SmartPay | `smartpay_record_invoice(...)` |
| Приём webhook | `smartpay_apply_webhook(payload)`, дедуп по `payment_id` |
| Создание счёта | Edge Function `smartpay-invoice`, `verify_jwt: true` |
| Приём уведомления | Edge Function `smartpay-webhook`, `verify_jwt: false` |
| Экран оплаты | `lib/features/payment/`, роут `/pay/:venueId` |
| Тестовая наклейка | код `TEST` в `venue_qr_codes` → SAPPORO |

Секреты Edge Functions выставлены все: `SMARTPAY_API_KEY`,
`SMARTPAY_BASE_URL`, `SMARTPAY_RETURN_URL`, `SMARTPAY_WEBHOOK_TOKEN`,
`SMARTPAY_WEBHOOK_SECRET`, `SMARTPAY_DIAG_TOKEN`.

Webhook заведён в кабинете 8 сентября 2026 на адрес
`https://<project>.supabase.co/functions/v1/smartpay-webhook` с включённой
подписью. Токен приходит в заголовке `X-Api-Token`, он же лежит в секретах.

Проверено сквозным тестом: чужой токен — 403, битая подпись — 403, верная
пара — `applied` и платёж в базе становится `charged` с суммой, банком и
номером инвойса, повтор того же события — `duplicate` и 200.

Проверено вживую 8 сентября 2026:

- `GET /banks` отвечает 200, тринадцать банков — ключ рабочий на sandbox.
- `POST /invoices` создаёт счёт: `result: 200`, приходят `invoice_uuid`,
  `smartpay_id`, `payment_link`. Страница оплаты открывается (HTTP 200).
- Диплинк приходит по всем тринадцати банкам, схемы разные — см.
  `deeplinks.md`. Семь кастомных схем объявлены в манифестах iOS и Android.
- Расчёт скидки: акция «Второй рамен −40%», чек 100 сомони → скидка 40,
  к оплате 60.
- Создание счёта без пользователя отклоняется (401), webhook без токена
  отклоняется (403).

Для проверки шлюза без гостя у `smartpay-invoice` есть действие `probe`:
создаёт счёт на 2 сомони, ничего не пишет в таблицу платежей. Работает
только в sandbox и только с заголовком `x-diag-token`, совпадающим с
секретом `SMARTPAY_DIAG_TOKEN`. В production отвечает 403 при любом токене.

Живой ответ `GET /banks` шире таблицы из документации: там тринадцать
банков, включая MyBabilon с `id -10`, Ориёнбанк (3) и Душанбе Сити Банк (6),
которых в документации нет. Названия тоже другие — «ОАО «Алиф Банк»» вместо
«Алиф Банк». Рисовать кнопки по документации нельзя, только по ответу.

## Архитектура

Ключ `x-app-token` не должен попадать во Flutter-клиент ни в каком виде,
включая `--dart-define`: приложение распаковывается, строка достаётся. В проекте
уже принят этот принцип — `lib/core/env/env.dart` пускает внутрь только
публичный anon-ключ Supabase, потому что вся защита на RLS.

Значит:

```
Flutter ──▶ Supabase Edge Function ──▶ SmartPay API
                    (x-app-token живёт здесь, в secrets)
Flutter ◀── payment_link / deeplink_url
SmartPay ──webhook──▶ Supabase Edge Function ──▶ таблица платежей ──▶ Realtime ──▶ Flutter
```

Две функции:

1. **create-payment** — принимает от клиента заказ, проверяет по своей базе,
   что счёт настоящий и сумма правильная, зовёт `POST /invoices`, возвращает
   ссылки. Сумму никогда не брать из клиента без проверки.
2. **smartpay-webhook** — принимает уведомление, сверяет `X-Api-Token`,
   проверяет HMAC-подпись, дедуплицирует по `payment_id`, переводит заказ в
   оплаченный, отвечает `200 OK`. Отвечать 200 даже на повтор, иначе SmartPay
   будет долбиться двое суток.

Образец Edge Function в проекте — `supabase/functions/send-push/index.ts`:
Deno, `jsr:@supabase/supabase-js@2`, service-role клиент из `Deno.env`.

О статусе Flutter узнаёт не поллингом SmartPay, а подпиской на свою таблицу
через Supabase Realtime — этот механизм в проекте уже есть.

## Что положить в базу

Таблица платежей должна хранить и то, что вернул SmartPay, и то, что пришло в
webhook: `order_id` (свой), `invoice_uuid`, `smartpay_id`, `payment_id`,
`invoice_number`, статус, сумму в дирамах как целое, банк, время оплаты, сырое
тело webhook. Уникальный индекс по `payment_id` — это и есть идемпотентность.

Деньги в целых дирамах, не в double. `amount` в webhook уже целое число дирам,
так и хранить.

## Диплинки на мобильном

Для Blast диплинки уместнее страницы оплаты: гость и так в телефоне, у него
установлено приложение банка. Флоу — показать кнопки банков из `GET /banks`,
по нажатию создать инвойс с `deeplink_bank_id`, открыть `deeplink_url` через
`url_launcher` с `LaunchMode.externalApplication`, при неудаче откатиться на
`payment_link`.

Список банков кэшировать. Логотипы банков SmartPay отдаёт относительными
путями от `https://smartpay.tj`.

## Субагенты — это про модель Blast

Схема «гость платит, заведение получает деньги, Blast удерживает процент» в
терминах SmartPay называется splitting accounts: заведение — субагент, Blast —
платформа. Настраивается в кабинете, не через API. См. `dashboard.md`.

Это меняет юридическую рамку: Blast перестаёт быть только витриной и начинает
касаться чужих денег. Прежде чем писать код, нужно решение по договорам с
заведениями и по проценту.

## Порядок подключения

1. Заполнить форму на подключение sandbox: данные организации, ИНН, банковские
   реквизиты, контактное лицо. Получить доступ к кабинету.
2. Создать Test-ключ в кабинете. Положить в секреты Supabase, не в репозиторий.
3. `GET /health` — убедиться, что ключ живой, забрать `merchant_unit_uuid`.
4. Поднять `smartpay-webhook`, зарегистрировать URL в кабинете, включить
   подпись, сохранить секрет.
5. `POST /invoices` на минимальной сумме, пройти оплату в sandbox, поймать
   webhook, сверить подпись.
6. Только потом — production-ключ, он показывается один раз.

## Открытые вопросы к SmartPay

Ни в документации, ни в бандле сайта ответов нет:

- Возвраты и частичная отмена — есть ли API вообще. Экран оплаты умеет
  принять деньги и не умеет вернуть их.
- Как заводится webhook: токен и секрет подписи выдаются в кабинете, доступа
  к кабинету у интеграции пока нет.
- Отмена hold: в кабинете кнопка есть, эндпоинта нет.
- Существует ли `GET /order/status/{order_id}` из «Введения». Страница инвойсов
  утверждает, что поллинга нет.
- Тестовые карты и тестовые кошельки для sandbox.
- Лимиты частоты запросов.
- Реальная комиссия для Blast и условия splitting accounts.
- Фискальные чеки: кто их выбивает при оплате через SmartPay.
