# SmartPay — платёжный шлюз для Blast

SmartPay Ecommerce API v2. Онлайн-эквайринг Таджикистана: электронные кошельки,
карты Visa/Mastercard/AMEX, Apple Pay, Google Pay, диплинки мобильных банков.
Валюта одна — сомони (TJS).

## Главное за 30 секунд

| | |
|---|---|
| Аутентификация | заголовок `x-app-token: <ключ>` в каждом запросе |
| Sandbox | `https://sandbox.smartpay.tj/api/merchant` |
| Production | `https://ecomm.smartpay.tj/api/merchant` |
| Эндпоинтов всего три | `GET /health`, `GET /banks`, `POST /invoices` |
| Как узнать, что оплатили | **только webhook**, поллинга нет |
| Личный кабинет | `https://dashboard.smartpay.tj` |

Весь путь интеграции: получить ключ → `GET /health` (вернёт `merchant_unit_uuid`)
→ `POST /invoices` (вернёт `payment_link` или `deeplink_url`) → увести клиента
по ссылке → принять webhook.

## Пять правил, которые ломают интеграцию чаще всего

1. **HTTP 200 не значит успех.** Бизнес-результат живёт в поле `result` тела
   ответа. `result: 200` — успех, `result: 400` — ошибка. Проверяй `result`
   всегда.
2. **Поллинга статуса не существует.** Страница «Введение» упоминает
   `GET /order/status/{order_id}`, но такого раздела в документации нет, а
   страница инвойсов говорит прямо: «Опрос статуса (polling) не предусмотрен».
   Считай источником истины webhook. Перед реализацией поллинга — спроси
   аккаунт-менеджера, существует ли эндпоинт.
3. **Единицы суммы разные в запросе и в webhook.** В `POST /invoices` поле
   `amount` — сомони (`150.5` = 150 сомони 50 дирам). В webhook `amount` —
   **дирамы целым числом** (`1500000` = 15 000 сомони). Делить на 100.
4. **`x-app-token` не должен попадать в приложение.** Ключ живёт только на
   сервере. Для Blast это Supabase Edge Function, не Flutter-клиент.
5. **Идемпотентность по `order_id`.** Повторный `POST /invoices` с тем же
   `order_id` вернёт существующий инвойс, а не создаст второй. Это защита от
   двойного списания, пользуйся ей осознанно.

## Границы того, что известно

Документация покрывает мерчантский API. В бандле сайта есть ещё раздел Bank API
(`bank-get-invoice`, `bank-pay-invoice`, `bank-get-transactions`) — он для
банков-партнёров, не для мерчанта, и в мерчантскую интеграцию не входит.

Не задокументировано нигде и требует вопроса менеджеру SmartPay:
возвраты (refund), частичная отмена, отмена hold через API, тестовые карты для
sandbox, лимиты по частоте запросов, реальный размер комиссии для Blast.
