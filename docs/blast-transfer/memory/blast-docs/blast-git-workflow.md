Любые правки кода в проектах Blast вести в новой ветке от main и оформлять pull request, а не коммитить прямо в main. Сказано 13.09.2026 во время подготовки Android-релиза.

**Why:** main остаётся собираемым и деплоимым в любой момент, а изменения видно одним диффом до вливания.

**How to apply:** перед первой правкой создавать ветку с говорящим именем (например `android/play-release`), коммитить туда, в конце открывать PR на main через `gh pr create`. Это относится к репозиторию приложения [[blast-app-repo]] и к сайту; к миграциям Supabase, которые применяются через MCP, git-ветки неприменимы — там изменение уходит сразу в базу, и это надо проговаривать отдельно.

**GitHub CLI не установлен** (проверено 29.09.2026: `gh` нет ни в PATH, ни в /opt/homebrew/bin). PR открывать нельзя — пушить ветку и отдавать ссылку `https://github.com/bakhtovar/<repo>/pull/new/<branch>`. Репозиторий приложения на GitHub — `bakhtovar/Blast-Pay`.
