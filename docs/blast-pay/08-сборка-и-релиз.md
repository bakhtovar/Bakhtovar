# 08 · Сборка и релиз

## Команды

```bash
make setup     # первый запуск: зависимости, gen-l10n, токены, кодоген, формат
make run       # запуск; make run DEVICE=<id из flutter devices>
make ipa       # сборка для App Store (RELEASE_ENV=prod)
make aab       # сборка для Google Play
make gen       # кодоген freezed / riverpod / drift / json
make tokens    # design-tokens.json → lib/app/theme/tokens.dart
make test      # 242 теста
make analyze   # flutter analyze + custom_lint
make fmt       # dart format
make db-reset  # накатить миграции локально заново
make db-test   # pgTAP
```

Строки локализации после правки `.arb`:
```bash
python3 tool/gen_strings.py
```

## Железное правило сборки

**Никогда не собирать релиз из Xcode и никогда не запускать `flutter run`
напрямую.**

Xcode про `--dart-define` не знает. Он берёт `DART_DEFINES` из
`ios/Flutter/Generated.xcconfig`, а туда их пишет последняя выполненная команда
`flutter`. Архив, собранный из Xcode, унесёт в App Store окружение последнего
`make run` — в лучшем случае staging, на чистой машине пустой `SUPABASE_URL`
и белый экран у каждого, кто скачает.

Отдельно: **`flutter build ios --config-only` стирает `DART_DEFINES`** из
`Generated.xcconfig`. Если пришлось её выполнить — повторите с полным набором
`--dart-define` из `.env.local`, иначе следующий архив уедет пустым.

`make ipa` собирает сам и следом выгружает dSYM в Crashlytics **отдельной
строкой рецепта**. Отдельной не для красоты: make выполняет каждую строку своей
оболочкой и останавливается на первой упавшей. Припиши выгрузку к той же
команде через `;` — её `exit 0` съест код возврата `flutter build ipa`, и
провалившийся релиз отрапортует успехом.

## Версии

**Работаем на 1.0.3. Меняется только номер сборки.**

```
version: 1.0.3+10  →  1.0.3+11  →  1.0.3+12
```

Обе платформы берут номер из `pubspec.yaml`: iOS через `FLUTTER_BUILD_NAME` /
`FLUTTER_BUILD_NUMBER`, Android через `flutter.versionName` / `versionCode`.

Пока версия в App Store Connect в статусе *Prepare for Submission* или
*Rejected*, внутрь неё можно грузить сколько угодно сборок и подменять
прикреплённую. Новую версию создавать не нужно.

Поднимать до 1.0.4 — только после того, как 1.0.3 станет *Ready for
Distribution*.

**Почему это записано так жёстко.** 15 сентября 2026 версию 1.0.2 одобрили
вечером, и загрузка 1.0.2 (10) отлетела с двумя ошибками:

- `90062` — номер версии должен быть выше уже одобренного;
- `90186` — «поезд» версии 1.0.2 закрыт.

Пришлось поднимать до 1.0.3. App Store замораживает версию после одобрения.

Израсходованные номера сборок: iOS — 1.0.2 (3–6) и 1.1.0 (9); Android — 7 и 8.
Номер обязан расти и не пересекаться с занятыми.

## Публикация в App Store

1. `make ipa`
2. Xcode → Organizer → Distribute App (или Transporter). Xcode здесь **только
   загрузчик**, не сборщик.
3. App Store Connect → версия 1.0.3 → Build → выбрать сборку.
4. App Privacy: **Crash Data** должна быть объявлена (Diagnostics → Crash Data,
   Linked to You: **No**, Tracking: **No**). Идентификатор пользователя в
   Crashlytics сознательно не передаётся — именно чтобы честно стоял «No».
5. Submit.

## Публикация в Google Play

1. `make aab`
2. Рецепт сам напечатает владельца сертификата подписи — сверить, что это не
   отладочный ключ.
3. `android/key.properties` и keystore обязаны существовать, иначе бандл
   подпишется отладочным ключом и Play его отклонит.

## Crashlytics

Работает на обеих платформах. Инициализация — только из Dart, через
`FirebaseOptions` из `--dart-define`. **`google-services.json` и
`GoogleService-Info.plist` в репозитории нет и не нужно.**

Файлы нужны не отчётам, а расшифровке нативных кадров. Стеки Dart приезжают
читаемыми: `--obfuscate` в сборках нет.

- **iOS:** закрыто. `upload-symbols` принимает идентификатор приложения флагом
  `-ai`, выгрузка встроена в `make ipa`.
- **Android:** mapping для R8 пока не выгружается — открытая задача.

Проверить связку, не собирая релиз:
```bash
make run CRASHLYTICS_IN_DEBUG=true
```
По умолчанию отладочные падения не уходят: они мешались бы с настоящими и
портили «процент сессий без сбоев».

## Полезные мелочи

- CocoaPods на этой машине падает с `Encoding::CompatibilityError` из-за
  кириллицы в пути. Лечится префиксом:
  ```bash
  LANG=en_US.UTF-8 LC_ALL=en_US.UTF-8 pod install
  ```
- Симулятор: bundle id `com.blastpay.app` (iOS), `com.blastpay` (Android).
  `simctl terminate/launch` с чужим id молчит и рапортует успехом.
- «You can't write reviews while using a prerelease version of iOS» — Apple
  считает сборку предрелизной. Проверять в Настройках → Основные → Об этом
  устройстве и в Обновление ПО → Бета-обновления.
