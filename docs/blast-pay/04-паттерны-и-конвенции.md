# 04 · Паттерны и конвенции

## Деньги — только целые дирамы

```dart
Money.perSomoni == 100;   // 12000 дирамов = 120,00 с.
```

`double` для денег запрещён: округление даёт расхождение между «сэкономлено» у
гостя и отчётом мерчанта, а такой спор нечем закрыть. Сомони появляются ровно в
двух местах: в `Money.format` и в поле ввода суммы.

**Ловушка, которая стоила бага:** база хранит `discount_fixed` и `max_discount`
**в сомони**, а приложение считает в дирамах. Умножать на `Money.perSomoni`
надо при разборе JSON, а не потом. Именно на этом «при оплате сумма считалась
неправильно».

Округление процента — банковское, как в SQL:
```dart
int _percentOf(int base, int percent) => (base * percent + 50) ~/ 100;
```

## Текст — через `Lx`, статически

```dart
Text(Lx.t('oplatit'))
Text(Lx.p('visits', count))   // формы множественного числа
```

Доступ статический, а не через `context`: строки нужны и в репозиториях, и в
статических методах, где `BuildContext` взять неоткуда.

Цепочка: `lib/l10n/app_{ru,tg,en}.arb` → `python3 tool/gen_strings.py` →
`strings_ru.dart` и соседи. Сгенерированные файлы править бесполезно.

## Смертельная ловушка `const`

```dart
const Text('...')                     // хорошо
const MyWidget()                      // если внутри Lx или BlastColors — БАГ
```

Flutter канонизирует `const`-виджеты: два одинаковых `const MyWidget()`
становятся **одним объектом**, который не перестроится ни при смене языка, ни
при смене темы. Виджет застывает на языке, который был при первой сборке.

Способ защититься, который уже применён к `AuthLegal` и `_OrLine`: **сделать
конструктор не-`const`**, тогда `const MyWidget()` просто не скомпилируется.

В коде осталось около 106 таких виджетов — незакрытая задача, см.
`09-открытые-вопросы.md`.

## Ошибки

Один тип — `AppException` с кодом. Один приёмник — `log`:

```dart
log.e(error, stack, code: 'payment.quote');   // нефатально
log.fatal(error, stack);                      // падение
```

`log` — единственная воронка: пишет в консоль и отдаёт в `CrashReporter`.
`CrashReporter` — прослойка над Crashlytics, чтобы без Firebase ничего не
падало. Отправляется `exception.cause ?? error` (иначе Crashlytics склеит все
ошибки в одну группу по типу `AppException`) и `code` как `reason`.

Идентификатор пользователя в Crashlytics **сознательно не передаётся** — чтобы
в анкете App Privacy честно стояло «Linked to You: No».

Глобальные перехватчики стоят в `main.dart`:
```dart
FlutterError.onError = (d) => log.fatal(d.exception, d.stack);
PlatformDispatcher.instance.onError = (e, s) { log.fatal(e, s); return true; };
```

## Riverpod

- Провайдеры **не** `autoDispose`.
- Следствие: ошибка провайдера переживает выход и вход. При смене пользователя
  кэш надо ронять руками через `ref.invalidate`.
- `ProviderContainer` создаётся в `main()` до `runApp` — чтобы удалённый конфиг
  и офлайн-очередь поднялись до первого кадра.

## Разрешения

Порядок жёсткий и системный, срабатывает один раз при первом запуске:

```
запуск → геолокация → уведомления
```

Флаг `permissions.asked` в `SharedPreferences`, вызов из `initState` через
`addPostFrameCallback`. Провайдер позиции только **читает** разрешение и
никогда не запрашивает: иначе системный диалог выскакивал бы в случайный момент.

## Секреты

Ключей в репозитории нет ни одного. Всё приходит через `--dart-define` из
`.env.local` (в `.gitignore`). Поэтому:

> **Запускать только через `make run`.** `flutter run` напрямую даст белый экран
> без единой ошибки: `String.fromEnvironment` вернёт пустую строку, Supabase
> не поднимется.

То же с релизом: `flutter build ios --config-only` **стирает** `DART_DEFINES`
из `ios/Flutter/Generated.xcconfig`, и архив из Xcode уедет в App Store с
пустым `SUPABASE_URL`. Релиз собирается только через `make ipa` / `make aab`.

## Стиль кода

- Комментарии на русском, объясняют **почему**, а не что.
- Приватные виджеты `_Имя` живут в файле экрана.
- `switch`-выражения вместо `if`-лестниц.
- `abstract final class X { const X._(); }` для наборов статики.
- Форматирование `dart format`, длина строки 80.
