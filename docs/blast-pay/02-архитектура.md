# 02 · Архитектура

## Стек

| Слой | Чем |
|---|---|
| Приложение | Flutter 3.47, Dart 3.9 |
| Состояние | Riverpod 2 (`flutter_riverpod`, `riverpod_generator`) |
| Навигация | `go_router` 14 с `StatefulShellRoute` |
| Бэкенд | Supabase: Postgres, RLS, RPC, Edge Functions на Deno |
| Локальная база | `drift` (sqlite) — кэш каталога, офлайн-очередь, просмотренное |
| Модели | `freezed` + `json_serializable` |
| Карты | Apple Maps на iOS, растровый OSM (`flutter_map`) на Android |
| Пуши | APNs напрямую на iOS, FCM на Android |
| Падения | Firebase Crashlytics на обеих платформах |

Кодоген обязателен: `make gen` (freezed, riverpod, drift, json).

## Структура

```
lib/
  app/          каркас: роутер, оболочка с таббаром, тема
    theme/      палитра, токены, типографика, контроллер темы
  core/         то, что не про экраны
    analytics/  своя аналитика событий
    config/     удалённый конфиг (минимальная поддерживаемая сборка)
    env/        значения из --dart-define
    errors/     AppException, коды, маппер ошибок Supabase
    offline/    очередь отложенных операций, связность
    supabase/   клиент, провайдеры, обёртка над RPC
  features/     по одной папке на область
  l10n/         .arb — источник, .dart — сгенерированное
  shared/       общие виджеты и утилиты
```

**148 файлов Dart, ~38 000 строк. Тестов: 37 файлов, 242 теста.**

## Слои внутри фичи

```
features/payment/
  data/          репозиторий: ходит в Supabase, разбирает ответы
  domain/        модели и правила, без Flutter
  presentation/  экраны, виджеты, провайдеры
```

Так устроены не все фичи — мелкие обходятся одним `presentation`. Крупные
(`payment`, `catalog`, `activation`, `visits`) держат все три.

Размер фич: catalog 14 файлов, activation 12, payment 10, visits 9, profile 8,
notifications 7, reviews 7, auth 5, booking 5, access 4, staff 4, subscription 4.

`catalog_screens.dart` — самый большой файл проекта, около 3700 строк: главная,
поиск, карта, каталог, экран заведения и экран акции живут в нём вместе.

## Навигация

`StatefulShellRoute.indexedStack` с четырьмя ветками: Главная, Найти, Визиты,
Профиль. Оболочка — `lib/app/shell.dart`: своя плавающая капсула таббара со
стеклом, а не системный `NavigationBar`, плюс отдельная круглая кнопка QR.

**Важное следствие:** своя капсула не сообщает экранам, сколько места занимает.
Каждый список обязан сам оставлять запас `BlastSize.tabbarClearance`. На этом
уже трижды ловили обрезанный контент.

Редирект в роутере решает три вещи: пускать ли без входа, отправлять ли на экран
имени после регистрации, куда вести по ссылке из письма или наклейки.

## Состояние

Riverpod, провайдеры **не** `autoDispose`. Следствие: ошибка провайдера переживает
вход и выход — при смене пользователя кэш надо ронять руками
(`ref.invalidate`). Это уже кусалось.

`ProviderContainer` создаётся в `main()` до `runApp`, чтобы конфиг и офлайн-очередь
поднялись до первого кадра.

## Что где начинается

- `lib/main.dart` — обработчики ошибок, Supabase, Firebase, контейнер, `runApp`.
- `lib/app/app.dart` — `MaterialApp.router`, тема, локаль.
- `lib/app/router.dart` — маршруты и редирект.
- `lib/app/shell.dart` — таббар и оболочка вкладок.
