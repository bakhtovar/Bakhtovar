## 4. App Store Connect — заполнить руками

Это не в коде, ревьюер смотрит именно туда.

**App Privacy («nutrition labels»).** Должно совпадать с манифестом:
Contact Info (email, name) · Identifiers (user ID) · Location (precise) ·
Photos · Purchases (purchase history) · User Content (other user content) ·
Usage Data (product interaction). Всё — Linked to user, Not used for
tracking.

**Age Rating.** В акциях есть алкоголь: R-07 «Винный вечер» — дегустация
с сомелье. Ответ «Alcohol, Tobacco, or Drug Use or References: Infrequent/Mild»
даёт 12+. Занизить — отдельная причина отказа.

**Privacy Policy URL** — обязательное поле, см. блокер 5.1.1(i).

**Beta App Review Information.** Sign-in required — **не ставить**: пароля
нет. В Notes — текст из `docs/app-review-reply.md`.

**Название.** `Blast Pay` при отсутствии оплаты — риск по **2.3.1(a)** и
**2.3.7** (метаданные обещают то, чего нет). В `app_ru.arb` команда сама
писала: «“Pay” обещает гостю не то, чем продукт является». Решение твоё;
я бы либо убрал «Pay» из витрины до появления оплаты, либо держал ответ
наготове.

## 5. Оплата — на будущее, чтобы не переделывать

Ты собираешься подключить оплату. Правило одно, и оно жёсткое:

- **3.1.1** — подписка «Blast Плюс», лимиты активаций, любые цифровые
  функции приложения → **только In-App Purchase**. Карта, Корти Милли,
  внешняя ссылка — отказ.
- **3.1.3(e)** — оплата **чека в заведении** (еда, услуга, потребляется вне
  приложения) → IAP использовать **нельзя**, нужны Apple Pay или карта.

То есть две разные оплаты живут по разным правилам. Строка
`oplataKartoyKortiMilli` на экране подписки сейчас показана «под замком» —
когда подключишь оплату подписки, её надо убрать, иначе 3.1.1.

Экран подписки с ценами и «оплата пока недоступна» ревьюер может счесть
незавершённой функцией (2.1). Если спросят — это витрина тарифов, покупка
появится через IAP.

## 6. Что не проверял

- Скриншоты и описание в App Store Connect — их нет в репозитории.
- Поведение на реальном устройстве после снятия Always-ключа — нужен
  `pod install` и сборка на телефоне; на симуляторе геопозиция не та.
- Android: `INTERNET` объявлен только в debug/profile-манифестах, в release
  его даёт `google_sign_in_android`. Уберёте Google-вход — релиз останется
  без сети. Это не про Apple, но заметил.

## 7. Проверка 9 сентября 2026: пуши и готовность к загрузке

### Пуши — работают

Цепочка проверена по базе, не по коду: `push_tokens` — один активный
токен iOS (`environment = sandbox`), `notification_outbox` — 13 записей,
все `sent`, `last_error` пуст, `notification_log` — 13 строк. Задержка от
постановки в очередь до отправки около минуты: `dispatch-push` в pg_cron
ходит раз в минуту и дёргает Edge Function `send-push` (задеплоена,
версия 11) с `x-cron-key`. Секреты APNs на месте — иначе функция отвечает
503 и очередь не трогает, а она отправляет.

Что поправлено этой проверкой:

- `docs/APPLE_PUSH.md` называл App ID и `APNS_TOPIC` как `com.blastpay`.
  Настоящий bundle id — `com.blastpay.app`; тот, кто настроил бы APNs по
  этой инструкции, получил бы `DeviceTokenNotForTopic` на каждом пуше.
- `PrivacyInfo.xcprivacy` не объявлял `NSPrivacyCollectedDataTypeDeviceID`,
  хотя токен APNs хранится вместе с `user_id`. Добавлено; то же самое
  нужно отметить в App Privacy в App Store Connect (Identifiers → Device ID).
- Комментарий в `Info.plist` объяснял ключ `NSLocationAlwaysAndWhenInUse`,
  снятый ещё в предыдущем аудите. Переписан на то, как есть.

Не проверено и проверяется только на боевой сборке: **production-окружение
APNs**. Токен сейчас sandbox. В `Runner.entitlements` лежит
`aps-environment = development` — при архивации Xcode подменяет его на
`production` по профилю распространения, а приложение читает окружение из
`embedded.mobileprovision`, а не из флага компилятора. После первой сборки
в TestFlight убедиться, что в `push_tokens` появился `environment =
production`, и что тестовый пуш до него доходит.

### Блокеры загрузки, найденные сейчас

| Что | Почему это блокер | Чьё |
|---|---|---|
| **Архив из Xcode не несёт `--dart-define`** | Xcode берёт `DART_DEFINES` из `ios/Flutter/Generated.xcconfig`, а туда их пишет последняя команда `flutter`. Сейчас там лежит `ENV=staging` от `make run`. Архив, собранный на чистой машине, уедет в App Store с пустым `SUPABASE_URL` — белый экран на старте и отказ по 2.1 | ✅ Добавлена цель `make ipa`: собирает `flutter build ipa` с теми же define и `ENV=prod`. Xcode остаётся только для загрузки готового `.ipa` |
| **Очередь раннего доступа включена** | `app_config.early_access.enabled = true` — ревьюер увидит заглушку очереди вместо приложения. Отказ по 2.1 | ❌ **Твоё**, отключение контроля доступа мне не даёт классификатор. SQL ниже |
| **Домена `blast.tj` нет вовсе** | У реестра .tj он отвечает NXDOMAIN: ни делегирования, ни зоны. На него вели политика, условия, почта поддержки, QR-наклейки и ссылка «поделиться» | ✅ Приложение переведено на `blastpay.tj` — восемь мест в коде и три строки перевода |
| **У `blastpay.tj` нет сайта** | Зона поднята 11 сентября (NS ns1/ns2.navjucloud.tj), в ней только почта: MX на Zoho и SPF. **A-записи нет** ни на корне, ни на www — политика, условия и ссылка приглашения `blastpay.tj/u/КОД` открываются ошибкой | ❌ **Твоё.** A-запись и три страницы; хватит статики на Netlify или Pages |
| **Почта наполовину** | MX и SPF стоят, но нет DKIM (`zmail._domainkey`) и DMARC (`_dmarc`), и самого ящика `support@` | ❌ **Твоё.** Без DKIM письмо ревьюеру уйдёт в спам |
| **`TARGETED_DEVICE_FAMILY = "1,2"`** | Сборка заявляла поддержку iPad: Apple проверяла бы на iPad и потребовала бы iPad-скриншоты. Интерфейс рисовался под телефон | ✅ `"1"` — только iPhone. Заодно снят мёртвый `UISupportedInterfaceOrientations~ipad`. В App Store Connect iPad-скриншоты больше не спросят |
| **Разрешены альбомные ориентации на iPhone** | Все экраны свёрстаны под портрет; ревьюер поворачивает устройство | Решение твоё: оставить только `UIInterfaceOrientationPortrait` |

Отключить очередь на время ревью (выполнить владельцу в SQL Editor):

```sql
update public.app_config
   set value = jsonb_set(value, '{enabled}', 'false')
 where key = 'early_access';
```

Вернуть после ревью — то же самое с `'true'`.
