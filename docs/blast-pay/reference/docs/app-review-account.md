# Демо-аккаунт для App Store Review

Apple просит в Beta App Review Information «User Name» и «Password». До сих
пор дать их было нечем: в приложении нет паролей вовсе — только Sign in with
Apple, Google и ссылка на почту. Ревьюер не может открыть нашу почту, а без
входа он не видит ничего.

Здесь — как завести один аккаунт, который входит по паролю, не стоит в
очереди раннего доступа и может пройти сценарий скидки из Купертино.

Очередь при этом **остаётся включённой** для всех остальных: снимать её на
время ревью больше не нужно.

---

## 1. Клиент: вход по паролю

Уже в сборке. На экране входа под кнопкой «Вход по почте» появилась ссылка
**«Войти по паролю»** — она открывает поле пароля. Обычному гостю она
бесполезна: пароля у него нет и завести его в приложении негде. Работает
ровно для тех, кому пароль проставили руками.

## 2. Завести аккаунт

Проект — **Blast App Dev** (`lfudcjwkyctodeqaommv`, регион eu-central-1).
Именно на него смотрит приложение: `SUPABASE_URL` в `.env.local` и в
собранном .ipa указывает туда. Проект «Blast Pay» (`ddbkjhnbqdmdwqvivzhu`,
ap-south-1) — пустая заготовка от июня, в ней нет ни схемы, ни данных;
аккаунт, заведённый там, в приложение не войдёт.

Supabase → Authentication → Users → **Add user** → *Create new user*:

| Поле | Значение |
|---|---|
| Email | `review@blastpay.tj` |
| Password | тот, что уйдёт в App Store Connect |
| Auto Confirm User | **включить** — иначе Supabase будет ждать подтверждения почты |

Пароль в репозиторий не класть: он живёт в App Store Connect и в вашем
менеджере паролей.

## 3. Один SQL после создания

Всё, что нужно аккаунту, одним блоком — выполнить в SQL Editor проекта
**Blast App Dev** сразу после того, как пользователь заведён. Что именно он
делает — в следующем разделе.

```sql
-- Имя: чтобы ревьюера не спрашивали, как его зовут.
update auth.users
   set raw_user_meta_data = coalesce(raw_user_meta_data, '{}'::jsonb)
       || jsonb_build_object('display_name', 'App Review',
                             'name_step_complete', true)
 where email = 'review@blastpay.tj';

-- Мимо очереди раннего доступа и мимо гостевых лимитов.
insert into public.dev_testers (user_id, note, expires_at)
select id, 'App Store Review', now() + interval '120 days'
  from auth.users
 where email = 'review@blastpay.tj'
on conflict (user_id) do update
  set expires_at = excluded.expires_at, note = excluded.note;

-- Проверка: строка должна найтись.
select u.email, t.expires_at, public.has_early_access(u.id) as has_access
  from auth.users u
  left join public.dev_testers t on t.user_id = u.id
 where u.email = 'review@blastpay.tj';
```

Последний запрос обязан вернуть `has_access = true`. Если `false` —
аккаунт не создан или почта другая.

## 4. Что делают эти два запроса

**Имя.** После входа приложение спрашивает, как зовут гостя, — экран
`name_step_complete` в метаданных. Ревьюеру он не нужен и выглядит как
лишний барьер, поэтому имя проставляется заранее.

**`dev_testers`.** Та самая таблица, по которой `has_early_access` пускает
своих мимо очереди, а `activate_offer` не считает гостевые лимиты: дневной,
повтор акции, повтор заведения, активная активация, лимит и пауза промо.
Строка протухает сама по `expires_at`. После одобрения сборки её можно
убрать руками:

```sql
delete from public.dev_testers
 where user_id = (select id from auth.users where email = 'review@blastpay.tj');
```

## 5. Разрешить активацию из Купертино

Без этого шага ревьюер дойдёт до слайдера и упрётся: активация требует QR со
стола и присутствие в 150 метрах от заведения в Душанбе. Это главный
сценарий приложения, и отказывают именно за «не смогли проверить основную
функцию».

Миграция `supabase/migrations/20260911120000_dev_tester_skips_presence.sql`
снимает обе проверки для тех, кто в `dev_testers`. **Выполнить её должен
владелец**: это ослабление контроля присутствия, и мне такие изменения
инструмент не даёт применять.

Содержимое файла скопировать в SQL Editor и выполнить. Миграция
идемпотентна: второй запуск ничего не делает, а если функция изменилась и
якорь не найден — падает с понятной ошибкой, а не молча.

## 6. Проверить перед отправкой

С нового устройства (или после выхода из аккаунта):

1. Экран входа → «Войти по паролю» → почта и пароль → вход проходит.
2. Заглушки очереди нет, открывается главная.
3. Любая акция → слайдер → активация проходит без QR и без «подойдите ближе».
4. Оплата открывает выбор банка (дальше нужен банк Таджикистана — об этом
   в ответе ревьюеру сказано прямо).

## 7. Что написать в App Store Connect

Beta App Review Information → Sign-in required: **включить**, и вписать почту
и пароль. Текст для поля Notes — в `docs/app-review-reply.md`.
